## 머리말

현대의 자동차 전장 시스템에서 마이크로컨트롤러(Microcontroller Unit, MCU)의 역할은 중추적이다. 과거 기계적 장치들이 담당하던 제어 영역이 소프트웨어 알고리즘으로 대체됨에 따라, 엔지니어들은 제한된 하드웨어 자원 위에서 여러 기능을 동시에 수행하면서도 시간적 결정론(Determinism)을 보장해야 하는 난제에 직면하게 되었다. 이러한 복잡성을 해결하기 위해 실시간 운영체제(Real-Time Operating System, RTOS)의 도입은 선택이 아닌 필수적인 공학적 해법으로 자리 잡았다.

특히 인피니언(Infineon)의 TriCore 아키텍처는 파워트레인 및 섀시 제어 분야에서 표준 플랫폼으로 자리 잡고 있다. 고성능 실시간 제어에 특화된 이 아키텍처 위에서 운영체제를 구동한다는 것은, 단순히 C 언어로 코드를 작성하는 차원을 넘어 하드웨어의 특성과 소프트웨어의 논리가 유기적으로 결합됨을 의미한다. 따라서 TriCore의 동작 원리에 대한 이해 없이는 효율적이고 안전한 RTOS 기반 시스템을 설계하는 것이 불가능하다.

대다수의 엔지니어들은 `xTaskCreate()`와 같은 API 함수를 호출하여 태스크를 생성하고 시스템을 구동한다. 그러나 공학도로서 우리는 API가 '동작한다'는 표면적인 결과에 안주해서는 안 된다. 함수 호출이라는 추상화된 행위 이면에 감춰진 레지스터의 이동, 메모리 스택의 변화, 그리고 CPU 파이프라인의 동작 원리를 규명해야만, 복잡한 임베디드 시스템에서 발생하는 문제를 근원적으로 해결할 수 있기 때문이다.

본 기술 문서는 파편화된 지식의 나열을 지양하고, FreeRTOS 커널이 TriCore 하드웨어 위에서 어떻게 구동되는지 그 공학적 원리를 규명하는 데 주안점을 둔다. 특히 TriCore 고유의 **CSA(Context Save Area)** 메커니즘이 문맥 교환(Context Switching) 효율에 미치는 영향을 심층적으로 분석함으로써, 독자들이 RTOS의 추상적인 개념을 구체적인 하드웨어 제어 흐름으로 연결할 수 있도록 안내하고자 한다.

## 맺음말

실시간 운영체제를 학습한다는 것은 단순히 API 사용법을 익히는 것에 그치지 않는다. 스케줄러가 어떤 기준으로 다음 태스크를 선택하는지, 문맥 교환 시 어떤 레지스터들이 어디에 저장되는지, 그리고 태스크 간 통신에서 어떤 오버헤드가 발생하는지를 이해함으로써, 비로소 엔지니어는 시스템 전체를 통찰할 수 있는 역량을 갖추게 된다. 본서가 그 여정에 작은 길잡이가 되기를 바란다.
